# systems/ — game data for ASHFALL: Lakehead (v1)

These are pure JSON data files. Nothing in `js/` was modified. Design rationale and budget tables are in `DESIGN.md`.

```
systems/
  survival.json      stats, rates, thresholds, environment + weather modifiers, chapter climate
  items.json         88 items, legacy id aliases, starting loadouts
  loot_tables.json   container types, act modifiers, per-chapter areas, act gates, legacy world.js spots
  crafting.json      8 recipes (+1 story one-off)
  weapons.json       melee / ranged / thrown stats
  enemies.json       13 enemies, 3 set pieces, encounter groups, chapter curve (spawns from story hooks)
  progression.json   acts, chapters, gear gates, perks, economy/traders, budget targets
  difficulty.json    modes (default = tense_but_fair) + permadeath option
  budget_report*.json   GENERATED by tools/validate.py (do not hand-edit)
  tools/validate.py  validator + resource-budget calculator
```

## Conventions (all files)
- Ids are stable `snake_case`. **Chapter ids = story hooks ids `ch01`..`ch10`.** Location ids = `loc_*` from `story/gameplay_hooks.json`. Story item and enemy ids are used unchanged.
- Systems acts: `blackout` (ch01–02), `collapse` (ch03–04), `civil_war` (ch05–07), `nuclear_winter` (ch08–10). Story acts (1/2/3) are also recorded as `story_act`.
- Time: **real seconds** unless a field says `per_game_minute`. 1 real s = 3.4286 game min (`CFG.dayLenSec` 420).
- Distances are in metres (world units). Weights are in kg. `value` is barter value, where 1 `ration` = 10.
- Keys that start with `_` are comments. Skip them when iterating.

## survival.json
| Path | Type | Meaning |
|---|---|---|
| `time_model` | obj | day length, conversion factor, time-skip costs |
| `stats.<warmth\|satiety\|hydration\|stamina\|radiation\|health>` | obj | `code_field` (existing `player.stats` key), `range` [min,max], `start`, `base_drain.per_real_second` / `.per_game_minute`, `modifiers` {name: mult}, `thresholds` [{id,min,max,effects{}}] |
| `thresholds[].effects` | obj | `stamina_regen_mult`, `stamina_max`, `move_speed_mult`, `aim_sway_mult`, `health_per_real_second` (negative = damage), `health_max`, `satiety_drain_mult`, `no_sprint` |
| `stats.warmth.clothing_insulation` | obj | `1 - Π(1 - r_i)` over equipped items' `insulation`, capped at 0.75 |
| `stats.hydration.free_source` | obj | `eat_snow` interaction (anti-hard-lock) |
| `stats.radiation.zone_gain_per_real_second` | {zone: float} | `rad_low`, `rad_med`, `rad_high`, `fallout_rain_outdoors` |
| `status_effects.<id>` | obj | wet / bleeding / sick / fracture / pain_suppressed: source, effects, `cured_by` item ids |
| `environment_modifiers.<id>` | obj | `warmth_drain_mult` or `warmth_regen_per_real_second` (+ radius) |
| `weather_modifiers.<weather_type>` | obj | keys = hooks `weather_types`: `warmth_drain_mult`, `wet_per_real_second`, `radiation_zone_outdoors`, `visibility_m` |
| `chapter_climate.<chXX>` | obj | `act`, `story_act`, `date`, `temp_c`, `weather`, `ambient_cold` (warmth mult), `blizzard_chance`, `fallout_rain`, `outdoor_share` |

Warmth per tick:
```js
let mult = climate.ambient_cold * weather.warmth_drain_mult;
if (night) mult *= env.night.warmth_drain_mult * (weather.night_extra_mult || 1);
if (blizzard && !indoors) mult *= env.blizzard.warmth_drain_mult;
if (indoors) mult *= env.indoors_unheated.warmth_drain_mult;
if (wetness > 0) mult *= 1 + 0.75 * wetness;
const drain = S.stats.warmth.base_drain.per_real_second * mult * (1 - insulation) * diff.warmth_drain_mult;
warmth = nearFire ? Math.min(100, warmth + env.near_fire.warmth_regen_per_real_second * dt) : Math.max(0, warmth - drain * dt);
```

## loot_tables.json
- `container_types.<type>`: `{label, rolls:[min,max], empty_chance, entries:[{item, weight, qty:[min,max]}]}`. Types: kitchen_cabinet, fridge, medicine_cabinet, dumpster, car_trunk, wardrobe, toolbox, locker, military_crate, supply_cache, woodpile, corpse, gun_safe (rare, hand-placed; needs crowbar/bolt_cutters).
- `act_modifiers.<act>`: `{empty_chance_add, category_weight_mult:{category: mult}}`
- `item_act_gate`: `{item: first_act}` (weight 0 before that act)
- `item_act_weight_mult`: `{item: {act: mult}}`, an extra per-item multiplier for an act (missing = 1.0). E.g. `ammo_556` ×0.25 and `ar15` ×0.6 in collapse. Applies to containers AND enemy drops.
- `areas.<chXX>[]`: `{location, containers:{type: count}, guaranteed:{item: n}, category_bias?, rad_zones?, note?}`. The level designer places `count` containers of that type in the area.
- `legacy_world_spots.spots`: the existing `world.js` loot spots mapped to a container type and fixed contents.
- `roll_algorithm`: the exact steps (pseudo-code in the file).

```js
function rollContainer(type, act, area, diff) {
  const t = LT.container_types[type], am = LT.act_modifiers[act];
  if (Math.random() < Math.min(0.95, Math.max(0, t.empty_chance + am.empty_chance_add + diff.loot_empty_add))) return {};
  const gated = id => LT.item_act_gate[id] && ACTS.indexOf(act) < ACTS.indexOf(LT.item_act_gate[id]);
  const pool = t.entries.map(e => ({ e, w: gated(e.item) ? 0 :
      e.weight * am.category_weight_mult[ITEMS[e.item].category] * ((area.category_bias||{})[ITEMS[e.item].category] || 1)
      * ((LT.item_act_weight_mult[e.item]||{})[act] ?? 1) }));
  const out = {}, n = randInt(...t.rolls);
  for (let i = 0; i < n; i++) { const e = weightedPick(pool); const q = scaleQty(randInt(...e.qty), ITEMS[e.item].category, diff); out[e.item] = (out[e.item]||0) + q; }
  return out;   // feed to inventory.mergeLoot(inv, out)
}
```

## crafting.json
`recipes[]`: `{id, name, inputs:{item: n} (≤2 kinds), output:{id, qty} | {place,...} | {repair,...}, requires: "none"|"near_campfire", time_real_seconds}`. `story_recipes[]` has the same shape (`lake_cooler`, Ch1 only). This maps directly onto `inventory.craft()`: `in` → `inputs`, `out` → `output`, and `special:"campfire"` → `output.place == "campfire"`.

## Paper doll (inventory screen)

The inventory screen draws Dell as a paper doll. Equipped gear appears as stacked sprite layers.

**Fields**
| Where | Field | Type | Meaning |
|---|---|---|---|
| `items.json` clothing items | `paperdoll_layer` | string | `<slot>_<look>`, lowercase snake_case. The prefix must equal the item's `slot`. |
| `items.json` weapon items (+ `molotov`, `flare`, `torch`, `flashlight`) | `paperdoll_layer` | string | `main_hand_<look>` for weapons and thrown items; `off_hand_<look>` for the flashlight and a held torch. |
| `items.json` / `weapons.json` | `tint` | `#rrggbb`, optional | Multiply-tint for colour variants of a shared layer. |
| `items.json` / `weapons.json` | `two_handed` | bool, optional | When the equipped main-hand item has this set, hide the off-hand layer. |
| `weapons.json` melee/ranged/thrown | `paperdoll_layer`, `two_handed` | | Mirrors `items.json` (the validator enforces a match), so either lookup works. |
| `items.json` top level | `paperdoll` | obj | `canvas_px`, `asset_path`, `base_body`, `draw_order`, `flag_layers`, `rules` |
| `items.json` → `paperdoll.flag_layers[]` | `{flag, layer, slot}` | | Layers drawn from story flags instead of items. Currently only `has_gas_mask` → `face_gas_mask`. There is no gas-mask item. |

`mask_filter` has `slot: "face"` for the filter mechanic but **no layer**. It is a cartridge inside the mask.

**Engine contract**
- Asset file: `assets/paperdoll/<paperdoll_layer>.png`. Base body: `assets/paperdoll/base_body.png`.
- Every layer is **48×96 px** on the same canvas as the base body, with a transparent background, pre-positioned (no offsets) and front-facing. Pixel art uses the game palette.
- Draw order: `base_body` → **base, legs, feet, torso, hands, wrap, face, head** → **main_hand** → **off_hand**. At most one layer per slot.
- Gas mask: if story flag `has_gas_mask` is true, draw `face_gas_mask` in the face slot.
- Main hand = `player.equipped`, if that item has a layer. Off hand = `off_hand_flashlight` while the flashlight is on, or `off_hand_torch` while a torch is held. Skip the off hand if the main-hand item is `two_handed`.
- Tint: draw the layer, then multiply by `tint` (or use a pre-tinted cache). With no tint, draw the PNG as authored.
- Missing PNG: skip the layer silently, so the doll still renders while art is in progress.

```js
const ORDER = I.paperdoll.draw_order;               // base..head, main_hand, off_hand
function dollLayers(player, inv, flags) {
  const L = {};
  for (const id of player.equippedClothing) { const it = ITEMS[id]; L[it.slot] = it; }  // one per slot
  for (const f of I.paperdoll.flag_layers) if (flags[f.flag]) L[f.slot] = { paperdoll_layer: f.layer };
  const main = ITEMS[player.equipped]; if (main?.paperdoll_layer) L.main_hand = main;
  if (!main?.two_handed) {
    if (player.torchHeld) L.off_hand = ITEMS.torch; else if (player.flashlight) L.off_hand = ITEMS.flashlight;
  }
  return ORDER.filter(s => L[s]).map(s => ({ src: `assets/paperdoll/${L[s].paperdoll_layer}.png`, tint: L[s].tint }));
}
```

## How Echo should load it
The game is a static ES-module site, so fetch the files once at boot, the same way `js/story.js` loads story data:
```js
// js/systems.js
const SYS = "systems/";
const NAMES = ["survival","items","loot_tables","crafting","weapons","enemies","progression","difficulty"];
export async function loadSystems(modeId) {
  const d = Object.fromEntries(await Promise.all(NAMES.map(async n =>
    [n, await (await fetch(SYS + n + ".json", { cache: "no-store" })).json()])));
  d.ITEMS = Object.fromEntries(d.items.items.map(i => [i.id, i]));
  for (const [oldId, newId] of Object.entries(d.items.legacy_aliases)) d.ITEMS[oldId] = d.ITEMS[newId]; // keep old saves/code working
  d.WEAPONS = Object.fromEntries([...d.weapons.melee, ...d.weapons.ranged, ...d.weapons.thrown].map(w => [w.id, w]));
  d.ENEMIES = Object.fromEntries(d.enemies.enemies.map(e => [e.id, e]));
  d.MODE = d.difficulty.modes.find(m => m.id === (modeId || d.difficulty.default_mode)).multipliers;
  return d;
}
```
Then:
1. Replace the `ITEMS` / `RECIPES` constants in `config.js` with `SYS.ITEMS` / `SYS.crafting.recipes`.
2. Read rates in `tickSurvival` from `survival.json` and add `stats.thirst`.
3. Read `KINDS` from `ENEMIES` in `enemies.js`.
4. Roll `world.loot` from `loot_tables.areas[chapter]`.

## Validate
```
python3 systems/tools/validate.py                 # default mode, prints budget table, writes budget_report.json
python3 systems/tools/validate.py --mode whiteout  # any mode
```
The validator checks:
- JSON validity
- every cross-reference (recipe I/O, loot entries, guaranteed items, enemy drops, trader stock, gear gates, weapon ammo, starting loadouts)
- the recipe rules (5–8 recipes, ≤2 ingredients each)
- the default mode is the only default and is all-baseline
- enemy chapter gating
- no supernatural wording
- **story cross-reference:** every item/enemy id in `story/items.json`, `story/gameplay_hooks.json` (items, start_inventory, crafting, enemies, enemy_types) and `story/dialogue/*.json` (give/take/item) must exist in systems data, and the chapter spawns must match the hooks.

Exit code 1 means there are errors. Warnings are for budget ratios that fall outside their target band.
